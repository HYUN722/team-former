# 팀 편성 웹 앱

학번 2601975 · 이름 정수현

학생들이 팀 프로젝트를 위한 팀을 스스로 편성하는 웹 앱입니다.
학생은 팀에 지원하고 기존 팀원의 투표로 합류가 정해지며, 모집 마감 뒤 팀이 없는 학생은
AI가 배정안을 제안하고 앱이 그 배정안을 규칙으로 검사한 뒤 관리자가 확정합니다.

## 3. 고른 해결 방법

공고 3장의 표에서 기능마다 **어려운 해결**을 골랐습니다.

| 기능 | 고른 해결 | 구현 위치 |
| --- | --- | --- |
| 다른 사람의 변경 보기 | 어려운 해결 — `st.fragment(run_every=4)` 로 팀 목록과 지원 목록만 4초마다 다시 그림 | `streamlit_app.py` 의 `student_board`, `admin_board` |
| 필수 포함 역할을 지킬 수 없는 팀 | 어려운 해결 — 지원 단계에서, 지원자가 들어간 뒤 남는 자리가 아직 못 채운 필수 역할 수보다 적으면 막음 | `rules.check_join` |
| 같은 팀에 대기 중인 지원이 여럿 | 어려운 해결 — 전원 찬성이 모인 순간 규칙을 다시 검사함. 처리 순서는 지원 순서가 아니라 투표가 끝난 순서 | `db.cast_vote` |
| 마지막 자리에 두 명이 동시에 들어감 | 어려운 해결 — `tf_members (team_id, slot_no)` 기본 키와 `student_id` 유일 제약으로 DB가 막음 | `schema.sql` |
| AI 응답이 늦을 때 | 어려운 해결 — 모델마다 별도 스레드에 올려 **전체 대기 시간** 120초를 재고 끊음 | `ai_assign.call_model` |
| 3차 모델까지 실패 | 어려운 해결 — 앱이 완전 탐색(백트래킹)으로 다섯 가지 검사를 모두 통과하는 배정을 찾음 | `rules.solve_assignment` |
| AI 대기 중 화면 | 어려운 해결 — `assign_status` 에 "1차 모델의 응답을 기다리는 중" 처럼 몇 차인지 표시 | `streamlit_app.run_assignment` |
| DB가 일시정지되지 않게 | 어려운 해결 — GitHub Actions 로 매일 09:10(KST) 에 DB에 질의를 보냄 | `.github/workflows/keep-db-awake.yml` |

### 필수 포함 역할 자리 계산

기획자와 웹 프로그래머는 **서로 다른 사람**이 맡아야 하므로, 한 학생이 둘 다 할 수 있어도 하나로만 셉니다.
사람-역할 이분 매칭의 최대 매칭 크기로 "이미 채운 필수 역할 수"를 구합니다 (`rules.covered_required_roles`).

```
남은 필수역할 수 = 2 - 이미 채운 필수역할 수
지원자를 넣은 뒤 남는 자리 = 4 - (현재 인원 + 1)
남는 자리 < 남은 필수역할 수  ->  막음
```

부록 3(어려움) 11단계가 이 경우입니다. 팀3에 학생11(테스터)과 학생15(발표자)가 있을 때
학생14(보고서 작성자)가 지원하면, 넣은 뒤 남는 자리는 1개인데 아직 채워야 할 필수 역할은
기획자·웹 프로그래머 2개이므로 접수하지 않고 막습니다.

## 5. 오픈라우터 AI 모델 호출 실패 사례

**부록 3(어려움) 15단계**에서 모델 3개가 모두 다른 이유로 실패했고, 앱이 완전 탐색으로 배정을 만들었습니다.

| 차수 | 모델 | 실패 내용 | 앱이 한 일 |
| --- | --- | --- | --- |
| 1차 | `minimax/minimax-m3.1-flash:free` | `RuntimeError: HTTP 404` (없는 모델) | 2차로 넘어감 |
| 2차 | `xingchen-agi/xing4.0-29b-a4b:free` | **배정안이 규칙 검사에 걸림 — 팀2가 5명임 (최대 4명)** | 3차로 넘어감 |
| 3차 | `nvidia/nemotron-3.5-super-vl:free` | `ValueError: 빈 응답` | 완전 탐색으로 직접 계산 |

![AI 배정 실패 — 404, 규칙 검사 실패, 빈 응답](img/스크린샷%202026-10-26%20004122.png)

2차 모델은 **응답은 했지만 규칙을 어긴 배정안**을 냈습니다. 한 팀에 5명을 넣으려 한 것입니다.
앱이 공고 2.5절 4항의 다섯 가지 검사(`rules.validate_assignment`)로 이를 걸러 내고 다음 모델로 넘어갔습니다.
AI의 답을 그대로 믿었다면 규칙을 어긴 구성이 확정될 뻔한 경우입니다.

그 밖에 관찰한 실패 유형:

- 부록 1(쉬움) 6단계: 모델 3개가 모두 `HTTP 404`
- 부록 2(중간) 11단계: 1차 `HTTP 404`, 2차 `HTTP 429`(요청 과다), 3차 `TimeoutError: 120초 안에 응답하지 않음`

![부록 1 — 모델 3개 모두 404](img/스크린샷%202026-10-21%20043219.png)

![부록 2 — 404, 429, 120초 시간 초과](img/스크린샷%202026-10-23%20044958.png)

3차의 시간 초과는 `ai_assign.call_model` 이 모델마다 전체 대기 시간 120초를 재서 끊은 결과입니다.

앱은 모든 호출 결과를 `tf_ai_logs` 테이블에 남깁니다(차수, 모델 이름, 성공 여부, 걸린 시간, 실패 사유, 응답 앞부분).

## 6. 클로드가 잘못된 추론이나 답변을 한 사례

**클로드가 쓴 팀원 조회 SQL이 `group by` 와 `order by` 를 잘못 조합해 PostgreSQL `GroupingError` 를 냈습니다.**

```
psycopg.errors.GroupingError: column "m.slot_no" must appear in the GROUP BY clause
or be used in an aggregate function
LINE 9: order by m.slot_no
```

`db.py` 의 `_members_of` 가 학생별로 `group by s.id` 로 묶은 결과를 만들면서
정렬은 묶기 전 값인 `order by m.slot_no` 로 했기 때문입니다.

**알아챈 방법**: 관리자 화면에서는 드러나지 않았고, **부록 1(쉬움) 1단계**에서
학생 2026101이 팀1에 지원하는 순간 앱이 멈추며 처음 드러났습니다.
팀원이 없는 팀을 조회할 때는 정렬할 행이 없어 오류가 나지 않았기 때문입니다.
![GroupingError 화면](img/스크린샷%202026-10-20%20045830.png)

**고친 내용**: `order by min(m.slot_no)` 로 바꿨습니다.
`db.py` 1~2행의 수정일 주석(`2026-10-20 04:58 (KST)`)에 기록해 두었습니다.
(이 수정은 깃 저장소를 만들기 전에 이루어져 최초 커밋 `3ffa824` 에 포함되어 있습니다.)

그 밖에 관찰한 사례:

- 지원자 화면의 결과 안내가 다른 팀원의 투표 결과를 따라가지 못하는 문제를 클로드가 발견하고도
  "나중에 한꺼번에 고치자"고 판단했습니다. 공고 2.7절이 결과 안내의 첫 단어를 규정하고
  채점 프로그램이 그것을 읽으므로 즉시 고쳐야 하는 사안이었는데, 근거를 묻자
  "문제인 것은 확신하나 감점 여부는 확신하지 못한다"고 정정하고 바로 수정했습니다.
  부록 1 3단계에서 승인된 뒤에도 "대기…"가 남는 것으로 확인했고,
  `streamlit_app.py` 에 `watch_app_id` 를 두어 투표 결과를 따라가게 고쳤습니다.
- 오픈라우터 API 키를 만들 때 "Credit limit 칸은 비워 두라"고 안내했으나,
  실제 화면에서는 Expiration 과 Credit limit 이 모두 필수(*) 항목이라 비울 수 없었습니다.
  화면을 보고 바로 알아챘습니다.

  ![오픈라우터 API 키 생성 화면](img/스크린샷%202026-10-20%20041332.png)

## 7. 본인이 제출한 앱에서 발견한 문제점이나 개선 필요 사항

**오픈라우터 무료 모델 3개가 매번 실패해, 배정이 사실상 항상 앱의 완전 탐색으로 처리됩니다.
AI 배정 기능이 실질적으로 쓰이지 않고 있습니다.**

연습용 시나리오 3개를 모두 실행하는 동안 AI 배정이 성공한 적이 한 번도 없습니다.

| 시나리오 | 단계 | 결과 |
| --- | --- | --- |
| 부록 1(쉬움) | 6단계 | 3개 모두 404 → 완전 탐색 |
| 부록 2(중간) | 11단계 | 404, 429, 120초 시간 초과 → 완전 탐색 |
| 부록 3(어려움) | 15단계 | 404, 검사 실패, 빈 응답 → 완전 탐색 |

![부록 3 — AI 배정 실패](img/스크린샷%202026-10-26%20004122.png)

완전 탐색이 받아 주어 규칙을 지키는 배정은 매번 나왔지만, 공고가 요구한 AI 활용이
결과적으로 거의 이루어지지 않았다는 점이 문제입니다. 또 3차 모델까지 기다리는 동안
최대 6분 가까이 화면에 변화가 없어, 사용자가 멈춘 것으로 오해할 수 있습니다.

**개선 방향**: 무료 모델은 혼잡도에 따라 실패율이 높고 목록도 자주 바뀌므로,
모델 목록을 주기적으로 확인해 갱신하거나, 유료 모델을 쓸 수 있도록 설정을 분리하는 것이 필요합니다.
대기 시간 표시도 남은 초를 보여 주는 방식으로 바꾸면 오해를 줄일 수 있습니다.

## 9. 보안

- `OPENROUTER_API_KEY`, `DATABASE_URL`, `ADMIN_PASSWORD` 는 `.env`(로컬)와 Streamlit Secrets(배포)에만 둡니다.
  `.gitignore` 가 `.env` 를 걸러 내며, 코드에 값을 적지 않았습니다.
- 화면에는 키가 **있음/없음** 만 표시하고 값은 출력하지 않습니다.
- 비밀번호는 `bcrypt` 해시로 저장하고, 로그인할 때 해시를 비교합니다.
- 관리자 기능은 `is_admin` 인 계정만 볼 수 있습니다.
- 명단은 교수님이 나눠 준 가상 학생만 씁니다.
