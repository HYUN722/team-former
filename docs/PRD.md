# PRD — 팀 편성 웹 앱

학번 2601975 · 이름 정수현

## 1. 목적

학생들이 팀 프로젝트를 위한 팀을 스스로 편성하는 웹 앱을 만든다.
학생은 팀에 지원하고, 기존 팀원의 투표로 합류 여부가 정해진다.
모집이 끝난 뒤 팀을 찾지 못한 학생은 AI가 배정안을 제안하고, 앱이 그 배정안을 규칙으로 검사한 뒤 관리자가 확정한다.

핵심은 "AI를 믿지 않는 것"이다. AI는 배정안을 제안할 뿐이고, 규칙 검사와 실패 처리는 모두 앱이 책임진다.

## 2. 사용자

| 사용자 | 하는 일 |
| --- | --- |
| 학생 | 학번·비밀번호로 로그인. 팀 목록과 팀원(이름, 주 역할, 보조 역할)을 봄. 팀에 지원. 내 팀에 들어온 지원에 찬성/거부 |
| 관리자(교수) | 학번 `admin` 으로 로그인. 명단 CSV와 팀 수를 올려 초기화. 모집 마감. AI 배정안을 받아 확인하고 확정 |

- 관리자 계정은 앱이 시작할 때 비밀 값 `ADMIN_PASSWORD` 로 만들거나 비밀번호를 갱신한다.
- 명단을 다시 올려도 관리자 계정은 지우지 않는다.
- 학생 비밀번호는 모두 `1234` 이며, DB에는 bcrypt 해시로만 저장한다.

## 3. 도메인 규칙

### 3.1 역할

역할은 6개다: 기획자, 웹 프로그래머, 프론트엔드 디자이너, 테스터, 보고서 작성자, 발표자.

- 학생마다 주 역할 1개, 보조 역할 0~2개를 명단 CSV에서 받는다. 학생은 바꿀 수 없다.
- **주 역할**은 팀 안의 중복을 따지는 기준이다.
- **보조 역할**은 필수 포함 역할(기획자·웹 프로그래머)을 맡을 수 있는지 따질 때만 쓴다.

### 3.2 팀 규칙

| 규칙 | 내용 |
| --- | --- |
| 팀 수 | 명단을 올릴 때 지정한 수만큼 빈 팀(팀1, 팀2, …)을 만든다 |
| 인원 | 확정된 구성에서 모든 팀이 2~4명 (빈 팀 없음) |
| 주 역할 중복 | 한 팀에 주 역할이 같은 학생이 2명 이상이면 안 됨 |
| 필수 포함 역할 | 확정된 구성에서 모든 팀에 기획자 1명과 웹 프로그래머 1명이 **서로 다른 사람으로** 있어야 함. 주 역할이든 보조 역할이든 상관없음 |

### 3.3 지원

지원 단추를 누른 순간 앱이 규칙을 검사한다. 통과하지 못하면 접수하지 않고 `막힘: <이유>` 를 보여 준다.

막히는 경우:

1. 팀이 꽉 참(4명)
2. 같은 주 역할의 팀원이 있음
3. 이미 팀이 있음 — 지원 단추를 숨김
4. 결과를 기다리는 지원이 있음 — 지원 단추를 숨김
5. 모집이 마감됨 — 지원 단추를 숨김
6. 필수 포함 역할을 맡을 학생의 자리가 모자람 (어려운 해결)

**필수 포함 역할 자리 계산**: 지원자가 들어간 뒤 남는 자리 수 < 그 팀에서 아직 채우지 못한 필수 포함 역할 수 → 막는다.
기획자와 웹 프로그래머는 서로 다른 사람이 맡아야 하므로, 한 학생이 둘 다 할 수 있어도 1개로만 센다(이분 매칭의 최대 매칭 크기).

### 3.4 투표

| 상황 | 결과 |
| --- | --- |
| 빈 팀에 지원 | 투표할 팀원이 없으므로 바로 승인 |
| 팀원이 있는 팀에 지원 | 대기. 투표하는 시점의 팀원 전원이 투표 |
| 전원 찬성 | 승인 직전 재검사를 통과하면 승인 |
| 한 명이라도 거부 | 다른 팀원을 기다리지 않고 즉시 거절 |
| 아직 안 한 팀원이 있음 | 대기 |

- 한 번 한 투표는 바꿀 수 없다. 이미 투표한 지원에는 단추를 숨기고 "내 투표: 찬성"처럼 보여 준다.
- **승인 직전 재검사**(어려운 해결): 전원 찬성이 모인 순간, 정원·주 역할 중복·필수 포함 역할 자리를 다시 검사한다. 어기면 그 지원은 거절한다. 처리 순서는 지원 순서가 아니라 **투표가 끝난 순서**다.
- 막힘(접수 자체를 안 함)과 거절(접수된 뒤 떨어짐)은 다른 결과다.

### 3.5 마감과 배정

1. 관리자가 "모집 마감"을 누르면 그 뒤 지원·투표 불가.
2. 마감 시점의 대기 지원은 모두 거절. 1명뿐인 팀의 학생은 팀에서 빠져 "팀이 없는 학생"이 된다.
3. "AI 배정"을 누르면 현재 팀 구성·팀 없는 학생과 역할·규칙을 오픈라우터 모델에 보내 배정안을 받는다. **이미 팀에 있는 학생은 옮기지 않는다.**
4. 앱이 배정안을 5가지로 검사한다: ① 팀 없는 학생 전원 배정 ② 한 학생은 한 팀에만 ③ 모든 팀 2~4명 ④ 주 역할 중복 없음 ⑤ 필수 포함 역할 충족.
5. 무응답·빈 응답·오류·검사 실패 → 2차 모델 → 3차 모델. 모델마다 **전체 대기 시간 120초**를 재서 끊는다.
6. 3차까지 실패하면 앱이 스스로 5가지 검사를 모두 통과하는 배정을 완전 탐색으로 찾는다.
7. 검사를 통과한 배정안만 관리자에게 보여 주고, 확정하면 DB에 저장한다.
8. 규칙을 지키는 배정이 애초에 존재하지 않으면 AI를 부르지 않고 `assign_status` 에 "규칙을 지키는 배정이 없음"과 이유를 보여 준다.

## 4. 화면

### 4.1 공통

- 로그인 화면: 학번, 비밀번호, 로그인 단추
- 로그인한 사람 표시(`whoami`), 결과 안내(`result`)
- 결과 안내는 반드시 **승인 / 대기 / 거절 / 막힘** 중 하나로 시작한다

### 4.2 학생 화면

- 팀 목록: 팀마다 팀원 이름과 주 역할·보조 역할. 내 팀은 "내 팀"으로 구분 표시. 팀이 없으면 "아직 팀이 없음"
- 지원 단추: 이미 팀이 있거나, 대기 중인 지원이 있거나, 마감되었으면 숨김
- 내 팀에 들어온 지원마다 찬성/거부 단추. 이미 투표했으면 숨기고 내 투표를 표시

### 4.3 관리자 화면

- 명단 CSV 업로더, 팀 수 입력, 초기화 단추
- 모집 마감 단추
- 팀이 없는 학생 표시(`unassigned`)
- AI 배정 단추, 진행 안내(`assign_status`), 배정안 표, 확정 단추

### 4.4 Streamlit key (2.7절 — 틀리면 -5점)

| 요소 | key |
| --- | --- |
| 학번 입력칸 | `login_student_no` |
| 비밀번호 입력칸 | `login_password` |
| 로그인 단추 | `login_submit` |
| 로그인한 사람 표시 | `whoami` |
| 결과 안내 | `result` |
| 팀 표시 | `team_1`, `team_2`, … |
| 지원 단추 | `apply_1`, `apply_2`, … |
| 찬성 단추 | `vote_yes_{지원자 학번}` |
| 거부 단추 | `vote_no_{지원자 학번}` |
| 명단 CSV 업로더 | `admin_roster_file` |
| 팀 수 | `admin_team_count` |
| 초기화 단추 | `admin_start` |
| 모집 마감 단추 | `admin_close` |
| 팀 없는 학생 표시 | `unassigned` |
| AI 배정 단추 | `admin_assign` |
| 배정 진행 안내 | `assign_status` |
| 확정 단추 | `admin_confirm` |

## 5. 명단 CSV

UTF-8(BOM 포함 가능). `utf-8-sig` 로 읽는다.

```
student_no,name,main_role,sub_roles
2026001,가나다,기획자,보고서 작성자
2026002,라마바,웹 프로그래머,
2026003,사아자,테스터,기획자;발표자
```

업로드 시 지원·투표·팀원·마감 표시를 모두 지우고, 명단의 학생과 지정한 수만큼의 빈 팀을 새로 만든다.

## 6. 고른 해결 방법

모두 **어려운 해결**로 간다.

| 기능 | 선택 | 점수 |
| --- | --- | --- |
| 다른 사람의 변경 보기 | `st.fragment` 로 자동 갱신 | 1점 |
| 필수 포함 역할을 지킬 수 없는 팀 | 지원 단계에서 자리 모자라면 막음 | 7점 |
| 같은 팀에 대기 중인 지원이 여럿 | 승인 직전 재검사 | 3점 |
| 마지막 자리에 두 명이 동시에 | DB 유일성 제약 | 0.5점 |
| AI 응답이 늦을 때 | 모델마다 전체 대기 120초 | 1점 |
| 3차 모델까지 실패 | 완전 탐색으로 규칙을 지키는 배정 찾기 | (최대 6.5점 보호) |
| AI 대기 중 화면 | 몇 차 모델 대기 중인지 표시 | 1점 |
| DB 일시정지 방지 | 외부 예약 서비스로 매일 질의 | 0.5점 |

## 7. 비기능 요구사항

- 키(`OPENROUTER_API_KEY`, `DATABASE_URL`, `ADMIN_PASSWORD`)는 `.env` 와 Streamlit Secrets에만 둔다. 코드·깃허브·화면 어디에도 값을 출력하지 않는다.
- 테이블 이름은 모두 `tf_` 로 시작한다.
- DB 연결은 한 번만 만들어 재사용한다.
- 배포 서버 시각은 UTC이므로 화면에 시각을 보여 줄 때는 KST로 변환한다.
- 실제 사람의 이름·학번은 쓰지 않는다(README 작성자 표기 제외).
- 무료 모델 자동 라우터(`openrouter/free`)는 쓰지 않는다.

## 8. 범위 밖

- 학생이 역할을 바꾸는 기능
- 팀 이름 변경, 팀 해산
- 구글 로그인(`st.login`) — 채점자가 학생 여러 명으로 로그인할 수 없으므로 쓰지 않음
